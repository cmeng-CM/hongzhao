# work-closeout（收尾写回协议）

## 边界

- 仅在用户明确发出会话级收束请求（"收尾""收工""保存这次工作""closeout"）时运行；单点请求（记一条记忆、改一个文件）直接使用对应 Skill，不套本协议。
- 本 Skill 是分流器：自己不直接写长期记忆、项目契约或知识文件，判定产出类型后调用对应机制执行。
- 完成判据是"产生文件了吗"：每个确认项必须落盘并能指出具体文件；对话里说清不算完成。
- 命令统一为 `hongzhao <子命令>`，在记忆根目录执行，或用 `--root <路径>` 显式指定。

## 流程

```text
盘点产出 → 分流推荐（一次确认）→ 逐类执行落盘 → 汇总清单（必要时编译收口）
```

1. **盘点**：回顾本次会话，列出候选产出：完成了什么、决定了什么、梳理成型了什么。不虚构产出；没有可写回内容时直接说明并结束。
2. **分流**：按分流表归类，给出带目标位置的推荐清单，一次性请用户确认（可勾选、排除或补充）；只对归属有歧义的条目单独提问，一次一个。
3. **执行**：对确认项按分流表调用对应机制，逐类落盘。
4. **汇总**：输出写回清单（类型 + 文件 + 状态），报告跳过项及原因。

## 分流表

| 产出类型 | 判断标准 | 执行机制 |
|---|---|---|
| 项目进展、阶段变化、项目决策 | 改变项目 `current_state`、`next_action` 或资料入口 | `memory-project-context` 更新对应项目 `project-view.md` |
| 长期事实、偏好、经验 | 跨会话仍成立且值得长期保留 | `memory-write` 创建 raw 候选 |
| 梳理成型的知识 | 已整理为可复用的主题内容 | 知识正文归位到知识根目录；在记忆根执行 `hongzhao knowledge-register <路径>` 登记知识地图 |

同一产出只落一个去向；项目当前状态写契约，不重复写 raw。交接与日程类内容不在本协议范围内，由客户端自身机制处理。

## 执行细节

- 项目进展：先经 `registry/project-registry.yaml` 与项目 `project-view.md` 确认唯一对应项目，再按 `memory-project-context` 流程更新。
- 长期记忆：按 `memory-write` 的 scope 与 activation 判断规则执行，一条一档。
- 知识登记：知识正文先在知识根目录就位，再在记忆根执行 `hongzhao knowledge-register <知识根相对路径> --title <标题> --topic <topic> --summary <一句摘要>`；命令成功后自动重建派生文件并刷新全部启用的 inline 客户端快照。
- 编译收口：全部分流执行完成后判断——
  - 只有知识登记时无需额外编译（`knowledge-register` 已自动重建），在记忆根执行 `hongzhao doctor` 确认即可；
  - 产生了新 raw 候选时不自动编译；说明候选将在用户明确要求 `memory-compile` 时统一审阅编译。
- 任一步落盘失败时如实报告失败项，不宣称收尾完成。

## 输出

```text
收尾完成：
- 契约：[[<project-view 路径>]] — 更新了 <字段>
- 记忆：raw/<文件>.md（new，待编译）
- 知识：<路径> 已登记（已重建地图 / 待编译）
跳过：<条目> — <原因>
```

没有可写回内容时输出"本次会话无需写回"，不制造空文件。
